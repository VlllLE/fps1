# PlayerCharacter (procedural humanoid FPS body)

Drop-in full-body player under `Assets/Characters/Player/PlayerCharacter.prefab`.

The visible character is an **original Blender-built soldier** (no Asset Store, no downloaded
models or textures; everything is generated by `Tools/Blender/build_soldier.py`). The
bone hierarchy is still generated at runtime by `Assets/Scripts/Characters/`, and the soldier is
skinned onto those bones. If the imported model is missing or fails validation, the older
primitive-built procedural body is used instead (`HumanoidBody.UsesImportedModel` /
`ImportFallbackReason` say which one is active).

## Imported soldier (`Assets/Characters/Models/`)

| Asset | Role |
|-------|------|
| `Soldier.fbx` (+ `.glb` copy) | ~31k triangles, 4 skinned meshes on the 19 `HumanoidBone` names: `Soldier_Body` (torso, legs, vest, backpack, boots), `Soldier_Head` (face, helmet, headset, goggles, neck), `Soldier_ArmL/R` (sleeves, gloves, shoulder/elbow pads). Real-world size: feet at y=0, ~1.9 m including the radio antenna. |
| `SoldierArmsFP.fbx` (+ `.glb` copy) | ~8.6k triangles first-person arms, gloves and sleeves on 6 bones (UpperArm/Forearm/Hand L+R) matching the `ProceduralFirstPersonArms` IK rig. |
| `Soldier_AO.png`, `SoldierArmsFP_AO.png` | Baked ambient occlusion (UV0) used as the `_OcclusionMap`. |
| `Materials/Mat_Soldier_*.mat` | Armor, Cloth, Skin, Gear, Accent, Lens, Eye (Standard shader). The FBX importers remap to them. |
| `Resources/Characters/SoldierModelSet.asset` | `SoldierModelSet` ScriptableObject that references the models, materials and AO maps. |

How it is wired:

- `SoldierModelBinder` instantiates the FBX off-screen, skins its meshes to the authored rest pose,
  validates them (readable, known bones and materials, upright, height, facing; scale and a
  backwards import are corrected automatically) and re-binds them to the runtime bone transforms with
  bindposes taken from `HumanoidParts` rest positions. The `Soldier_Head` mesh lives under the `Head` bone
  and the arm meshes under `ShoulderL/R`, so `LocalPlayerBodyVisibility` still hides head, neck and arms
  from the first-person camera. Only the torso/leg mesh stays visible.
- Hit volumes (`Head`, `Body`, `Arm_*`, `Leg_*`), colliders and layers are unchanged and independent of the
  mesh. The mesh itself never carries a collider.
- `SoldierMaterials` maps `HumanoidPalette` onto the soldier: Cloth = suit, Armor = suitDark, Skin, Accent
  (team accent patches, tapes and cuffs), Lens = visor, Gear (webbing/pouches) derived from suit and
  suitDark, Eye fixed white. `SetPalette`, `HumanoidPalette.ForTarget` and the target hit flash work as before.
- Set `HumanoidBodySettings.forceProcedural` (or the inspector toggle on `HumanoidBody` /
  `ProceduralFirstPersonArms`) to skip the model.

Regenerate the assets (Blender 4.2, headless):

```
blender -b --factory-startup --python Tools/Blender/build_soldier.py -- \
    --out Assets/Characters/Models --renders <dir> [--samples 48] [--quick] [--no-render]
```

`--quick` uses Workbench renders and a small AO bake. Keep the `.meta` files (importer settings,
material remaps and GUIDs) when overwriting the FBX files.

The primitive procedural parts below are the fallback and are still fully supported.

## Scripts

The following components are in `Assets/Scripts/Characters/`:

| Script | Role |
|--------|------|
| `HumanoidBody` | Builds a 19-bone body under `BodyRoot`, sized to the `CharacterController` (feet at the capsule bottom, 2 m = standard height). Optional hit volumes for targets. |
| `HumanoidParts` / `HumanoidMeshBuilder` / `HumanoidMaterials` | Stylised limb, torso, head, boot and visor meshes plus a 5-slot suit palette (Standard shader). |
| `HumanoidAnimator` / `HumanoidIK` | Code-driven idle breathing, walk/strafe gait, crouch, slide, airborne, dive and weapon-ready arm poses using two-bone IK. No Animator clips needed. |
| `SoldierModelSet` / `SoldierModelBinder` / `SoldierMaterials` | Load the imported soldier, skin it to the runtime bones, create and tint its materials. |
| `ProceduralFirstPersonArms` | First-person arms on the camera. Hands IK to per-weapon grip points (`GunHoldCatalog`; melee keeps the fixed grips), so weapon attachment points are untouched. |
| `GunHoldProfile` / `GunHoldCatalog` | Per-weapon hold data: right grip, left grip/foregrip, stock, magwell and muzzle in weapon space, for Lowered / Ready / Aim stances. The weapon FBXs carry no grip empties, so values are a measured table; child objects named `RightGrip`, `LeftGrip`, `Stock` or `MuzzlePoint` on a weapon model override them. |
| `HumanoidAnimator.Hold` | Third-person gun holding: shoulder-stocked aim pose (stock in the shoulder pocket, weapon along the look direction, shooting elbow tucked, support elbow under the gun, head tilted to the sights), lowered ready pose, aim pitch spread over spine/chest/head, two-bone hand IK onto the gun, spring-based recoil scaled per weapon (`GunHoldProfile.recoilKick`), a braced leaning crouch for the LMG bipod stance, and a visible reload (magazine swap with the support hand). |
| `ThirdPersonGun` / `PlayerBodyWeaponSync` | Visual-only gun model on the soldier (bots, the player's own body). The sync component mirrors the player's current weapon, aim, sprint, reload and shots onto the body. |
| `DeathVariant` / `HumanoidDeathAnimator` / `DroppedGunPhysics` | Procedural death: variant chosen from hit direction, headshot, damage, speed and crouch (fall back, forward collapse, headshot snap-back, side falls, kneel). Bone-driven topple with spring settling, no ragdoll and no Animator. The gun drops and bounces to rest. |
| `DeathCamera` / `PlayerDeathPresentation` | Player death: the body falls, the camera blends to an orbiting third-person view and is restored on respawn. |
| `HumanoidBodyBootstrap` | At scene load, upgrades legacy primitive players and targets (old scenes/prefabs) to the procedural body. Idempotent. |

Bodies are rebuilt every time the scene loads and are not saved into scenes or prefabs
(`BodyRoot` uses `HideFlags.DontSaveInEditor`), so there is no baked mesh to go stale.
Select a `HumanoidBody` and use the context menu **Build** to preview it in the editor.

Movement, input and drift code only supplies velocity and state to the animator; it is not
modified.

**Status:** written without a Unity Editor run (the Blender side was rendered and checked headlessly; the FBX import, skinning at runtime and the new tests were only compile-checked). Open the project once and, if anything
looks off, regenerate via **Tools → Build Player Character Prefab**.

## Hierarchy

```
PlayerCharacter                    CharacterController + movement/input/weapon bridge + HumanoidBody
├── CameraHolder (y=1.6)           FirstPersonCamera
│   └── MainCamera                 culls PlayerLocalHide, ProceduralFirstPersonArms
│       ├── WeaponHolder / TestPistol
│       └── FirstPersonArms        generated FP arms (hands follow the weapon holder)
└── BodyRoot                       generated third-person / shadow body
    └── Hips
        ├── Spine > Chest > Neck > Head (+ ShoulderL/R > UpperArm > Forearm > Hand)
        └── ThighL/R > ShinL/R > FootL/R
```

Neck, Head and the shoulder chain (which carries the body arms) are hidden from the local
camera by `LocalPlayerBodyVisibility` (`PlayerLocalHide` layer); `HumanoidBody` registers
them through `SetHideTargets`. Legs stay visible when looking down.

Targets built by `HumanoidBody.AddTo(target, HumanoidBodySettings.Target(color, scale))`
keep direct-child `Head`, `Body`, `Arm_L/R`, `Leg_L/R` hit volumes (`HitZone`) that match
the mesh proportions.

The `Animations/PlayerAnimator.controller` is still an empty placeholder; animation is procedural.

## CharacterController (do not change when swapping)

Match the existing TestRange player so `MovementController` crouch/slide heights stay valid:

| Property | Value |
|----------|-------|
| Height   | 2     |
| Radius   | 0.4   |
| Center   | (0, 1, 0) |
| Slope Limit | 45 |
| Step Offset | 0.3 |
| Skin Width | 0.08 |

Eye height stays at **CameraHolder local Y = 1.6**.

## Swap TestRange capsule → this prefab

### Option A — Replace the whole player (recommended)

1. Open `Assets/Scenes/TestRange.unity`.
2. Note the existing `Player` transform position / rotation (default ~ `(0, 0.55, -5)`).
3. Delete the scene `Player` instance (the capsule body child `PlayerBody` goes with it).
4. Drag `Assets/Characters/Player/PlayerCharacter.prefab` into the scene.
5. Rename the instance to **`Player`** (PlayMode smoke tests and builders look up that name).
6. Confirm on the root:
   - `CharacterController` values match the table above (unchanged).
   - `MovementController.config` → `Assets/Configs/DefaultMovementConfig.asset`
   - `MovementController.cameraTransform` → child `MainCamera`
   - `InputHandler` present; `FirstPersonCamera.playerBody` → root transform
   - `PlayerWeaponBridge.weapon` → child `TestPistol`
7. Enter Play Mode: move, look down (legs visible), look around (no head in view).

Do **not** retune movement physics or class systems as part of this swap.

### Option B — Visual-only transplant (keep existing Player root)

1. Select scene `Player`.
2. Delete child `PlayerBody` (the capsule mesh).
3. Add `HumanoidBody` to the scene `Player` root and `ProceduralFirstPersonArms` to
   `MainCamera` (both build themselves on Awake).
4. Add `LocalPlayerBodyVisibility` to the root and assign `MainCamera`; `HumanoidBody`
   registers the hidden bones itself.
5. Leave `CharacterController`, `MovementController`, and configs untouched.

### Layer setup

Project Settings → Tags and Layers should include user layer **`PlayerLocalHide`**
(index 8). This PR adds it to `ProjectSettings/TagManager.asset`. The builder menu
also ensures the layer exists when regenerating the prefab.

For a remote / third-person pawn later, call
`LocalPlayerBodyVisibility.ConfigureAsRemotePlayer()` so the head is visible.

## Regenerate in Editor

`Tools → Build Player Character Prefab` rebuilds materials (if missing), the hide
layer, and overwrites `PlayerCharacter.prefab`. Safe to re-run; does not edit
`MovementConfig` assets.

## What this does not change

- `Assets/Prefabs/Player.prefab` and TestRange scene are left as-is until you swap.
- Movement physics defaults and class/loadout systems are untouched.
- No animation clips — the controller is still empty; `HumanoidAnimator` poses bones from code.
